Steps for running the analysis

To reproduce the results from this simulation, run the following steps. All model runs were run on the Open Science Grid (OSG), and an account is necessary use it. For a complete guide on how to get started with OSG see their website or this tutorial.

1. Build and publish the software container

Build the container once before submitting jobs. Use two PowerShell windows: the first is connected to the OSG access point and the second remains on your local computer in the repository root. The image is copied to the OSG data federation so HTCondor jobs can use it through osdf:///ospool/ap41/data/meg_oshima/linux-r4ss-v10.sif.

In the first PowerShell window, connect to OSG and create a build directory:

ssh meg_oshima@ap41.uw.osg-htc.org
mkdir -p /home/meg_oshima/singularity/linux_r4ss

In the second, local PowerShell window, upload the definition file from this repository:

scp osg_container/linux-r4ss-v2.def meg_oshima@ap41.uw.osg-htc.org:/home/meg_oshima/singularity/linux_r4ss/

Back on the OSG access point, build linux-r4ss-v10.sif, then publish it to the data directory used by the submit files.

cd /home/meg_oshima/singularity/linux_r4ss
apptainer build linux-r4ss-v10.sif linux-r4ss-v2.def
mkdir -p /ospool/ap41/data/meg_oshima
cp linux-r4ss-v10.sif /ospool/ap41/data/meg_oshima/
ls -lh /ospool/ap41/data/meg_oshima/linux-r4ss-v10.sif

When changing the definition file, build and publish a newly versioned .sif filename, then update the +SingularityImage path in the relevant HTCondor submit file. OSG caches images by filename. Verify the container works by running the following commands and checking the package versions of r4ss and ss3sim:

apptainer shell /ospool/ap41/data/meg_oshima/linux-r4ss-v10.sif
R 
utils::packageVersion("r4ss") #‘1.46.1’
utils::packageVersion("ss3sim") #‘1.21.0’
q()
exit #to exit apptainer

2. Prepare and submit a scenario

See steps_for_OM_EM_setup.qmd for how recruitment deviation and F matrices were created for the OMs. Run the code through Create the directories for OSG and target_dir.txt section to create inputs and scenario directories. The local Inputs directory should contain:

  • poor_recdevs_mat.RData
  • recdevs_mat.RData
  • setseed.csv
  • sas.csv
  • effN.csv
  • constantF_mat.RData

Choose the row matching the scenario directory you created. Use its preparation script and HTCondor submit file together; the submit file automatically transfers the corresponding R calculation script.

Also prepare the scripts directory to be uploaded to OSG.

shell(paste0(
    "powershell cd ",
    main.dir,
    ";tar -czf scripts.tar.gz ",
    "scripts"
))

Log in to OSG in a new powershell window.

#log in to OSG in powershell
ssh meg_oshima@ap41.uw.osg-htc.org
# put in password when prompted

Then in a second powershell window, upload your files.

# sceneario folder
scp upload.HRF_poorrec_25_yrfwd.tar.gz meg_oshima@ap41.uw.osg-htc.org:/home/meg_oshima/ 
# scripts 
scp scripts.tar.gz meg_oshima@ap41.uw.osg-htc.org:/home/meg_oshima/

In the active OSG window, untar the scenario and scripts directory and prepare the scripts for the job. Then submit the job.

tar -xzf scripts.tar.gz
chmod 777 scripts/osg-prep-HRF-poorrec.sh
tar -xzf upload.HRF_poorrec_25_yrfwd.tar.gz HRF_poorrec_25_yrfwd
./scripts/osg-prep-HRF-poorrec.sh
condor_submit scripts/condor_create_OMEM_HRF_poorrec.sub

To monitor the progress of a job run condor_q in the active OSG window. If a job completes very quickly, or is stuck on held status, you can check the job_.log and job_.err files which are found inside each respective iterations directory (e.g. HRF_poorrec_25_yrfwd/1/). When a job has finished there should be an End.tar.gz file in each iteration directory. ## 3. Retrieve results

Once the job has finished successfully, tar the scenario directory in the active OSG window and in the second powershell window, download the results.

tar -czf download.HRF_poorrec_25_yrfwd.tar.gz HRF_poorrec_25_yrfwd
# Download results 
scp meg_oshima@ap41.uw.osg-htc.org:/home/meg_oshima/download.HRF_poorrec_25_yrfwd.tar.gz ./download.HRF_poorrec_25_yrfwd.tar.gz

To unpack results return to steps_for_OM_EM_setup.qmd and run the code in Getting results section. To quickly visualize the results, run ./R/output_dashboard.qmd.
